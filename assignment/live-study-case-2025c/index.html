1. Tujuan dan Materi

Setiap tim membangun satu modul fungsional dari aplikasi yang dapat digabungkan menjadi satu alur sistem utuh. Tugas ini menguji penguasaan materi Reading Chapter 1 s.d. 6 yang telah dipelajari sampai pertemuan minggu lalu, yaitu:

  • Chapter 1 & 2: Pengenalan OOP, class dan object, atribut, serta instansiasi.
  • Chapter 3: Encapsulation, visibility, properties, dan validasi atribut.
  • Chapter 4: Class methods, static methods, dan function decorators.
  • Chapter 5: Inheritance, method overriding, dan hierarki class.
  • Chapter 6: Abstract base class (ABC), abstract method, dan penegakan kontrak interface.

Setiap paket tim sengaja dirancang memiliki satu konsep OOP utama yang wajib tampak dan dijelaskan saat presentasi, selain konsep dasar class dan object.

2. Skenario Sistem

Kampus menyediakan layanan peminjaman perlengkapan (seperti proyektor, kamera, dan speaker) kepada mahasiswa. Mahasiswa mengajukan peminjaman barang dengan menentukan tanggal pinjam dan rencana tanggal kembali. Petugas kampus memeriksa dan memutuskan pengajuan tersebut (menyetujui atau menolak). Saat barang dikembalikan oleh mahasiswa, sistem memproses penyelesaian transaksi dan menghitung denda keterlambatan jika pengembalian melewati batas waktu rencana.

Contoh Alur Demo Utama Mahasiswa mengajukan peminjaman proyektor, kemudian petugas menyetujui pengajuan tersebut. Saat barang dikembalikan 2 hari melewati tanggal rencana kembali, sistem menghitung denda keterlambatan sebesar Rp10.000 (tarif Rp5.000 per hari) dan mengembalikan status proyektor menjadi tersedia.

3. Batas Pekerjaan (Scope)

Wajib Dikerjakan

  • 1 barang per transaksi peminjaman.
  • Tahapan alur transaksi: Pengajuan, Keputusan Petugas (Disetujui atau Ditolak), hingga Pengembalian barang.
  • Validasi status transaksi, tanggal, dan batas durasi barang.
  • Pencatatan riwayat transaksi dan filter data.
  • Mampu menjalankan minimal 1 alur berhasil dan 2 kasus penolakan/gagal.
  • Data fixture sintetik bersama (identitas demo).

Di Luar Scope (Jangan Dibuat)

  • Database atau penyimpanan file permanen.
  • Password, token auth, atau login internal aplikasi.
  • Sistem pembayaran uang sungguhan, upload bukti, atau SMS/email notifikasi.
  • Multi-item cart/reservasi banyak barang sekaligus.
  • Framework web baru (Flask/Django/FastAPI) atau external HTTP API.

Gunakan Python standar (Standard Library) murni. Data pengguna dalam pengujian harus berupa data fixture sintetik (contoh: Mahasiswa("MHS01", "Budi")), dilarang menyalin NIM mahasiswa dari roster ke dalam kode. Jangan mengganti nama method interface yang telah disepakati atau mengakses atribut privat/internal milik class tim lain.

5. Paket Tujuh Tim: Rincian Fitur, Metode, Item OOP, dan Hint

Setiap kelompok bertanggung jawab atas satu modul utama. Untuk membantu pengerjaan tahap awal dan menjaga agar kode tidak keluar dari batasan yang disepakati, berikut adalah rincian lengkap mengenai item konsep OOP, daftar metode yang wajib dibuat, batasan aturan bisnis, serta petunjuk (hint) implementasinya:

Tim 1: Identitas Pengguna (pengguna.py)

Tanggung Jawab Fitur: Memodelkan data pengguna kampus dan membedakan hak akses antara mahasiswa dan petugas inventaris.

Item OOP yang Wajib Diterapkan:
  • Class & Constructor: Class induk Pengguna serta subclass Mahasiswa dan Petugas.
  • Encapsulation: Menyimpan atribut privat dengan awalan underscore: _identitas, _nama, dan _role.
  • Property (@property): Getter pembacaan publik untuk identitas, nama, role, serta alias nim dan nip.
  • Inheritance & super(): Subclass memanggil super().__init__(identitas, nama, role) dengan role otomatis.
  • Class Method Factory (@classmethod): Method dari_data(cls, data) untuk instansiasi dari dictionary fixture.
Metode yang Wajib Dibuat:
  • Pengguna.__init__(self, identitas: str, nama: str, role: str)
  • Pengguna.identitas(self) -> str (property)
  • Pengguna.nama(self) -> str (property)
  • Pengguna.role(self) -> str (property, nilai hanya 'mahasiswa' atau 'petugas')
  • Mahasiswa.__init__(self, nim: str, nama: str)
  • Mahasiswa.nim(self) -> str (property alias ke identitas)
  • Mahasiswa.dari_data(cls, data: dict) -> Mahasiswa (class method)
  • Petugas.__init__(self, nip: str, nama: str)
  • Petugas.nip(self) -> str (property alias ke identitas)
  • Petugas.dari_data(cls, data: dict) -> Petugas (class method)
Batasan dan Validasi Aturan Bisnis:
  • Validasi string: Jika identitas atau nama kosong (atau spasi saja), bangkitkan ValueError.
  • Validasi role: Jika role bukan 'mahasiswa' atau 'petugas', bangkitkan ValueError.
  • Validasi data fixture: Jika kunci 'nim'/'nip' atau 'nama' tidak ditemukan pada dictionary, bangkitkan KeyError.
Hint Awal untuk Tim 1: Jangan membuat setter untuk role agar peran pengguna bersifat read-only dan tidak dapat diubah sembarangan dari luar. Di dalam Mahasiswa.__init__, cukup panggil super().__init__(nim, nama, "mahasiswa") sehingga tidak perlu menulis ulang inisialisasi atribut nama dan identitas.
Unduh Starter Tim 1 (pengguna.py)

Tim 2: Katalog Perlengkapan (perlengkapan.py)

Tanggung Jawab Fitur: Memodelkan katalog barang inventaris kampus dengan batas pinjam yang berbeda-beda serta status ketersediaan.

Item OOP yang Wajib Diterapkan:
  • Abstract Base Class (ABC): Class dasar Perlengkapan mewarisi abc.ABC.
  • Abstract Method (@abstractmethod): Method batas_durasi_hari(self) -> int wajib dideklarasikan di class induk tanpa implementasi kode.
  • Polimorfisme & Method Overriding: Subclass konkret Proyektor, Kamera, dan Speaker mengimplementasikan durasi batas masing-masing.
  • Encapsulation: Menyimpan atribut privat _id_barang, _nama, dan status boolean _tersedia.
  • Controlled Mutation Method: Mengubah status ketersediaan hanya melalui method ubah_ketersediaan(status: bool).
Metode yang Wajib Dibuat:
  • Perlengkapan.__init__(self, id_barang: str, nama: str)
  • Perlengkapan.id_barang(self) -> str (property)
  • Perlengkapan.nama(self) -> str (property)
  • Perlengkapan.tersedia(self) -> bool (property, default awal True)
  • Perlengkapan.ubah_ketersediaan(self, status: bool) -> None
  • Perlengkapan.batas_durasi_hari(self) -> int (abstract method)
  • Proyektor.batas_durasi_hari(self) -> int (mengembalikan nilai 3)
  • Kamera.batas_durasi_hari(self) -> int (mengembalikan nilai 2)
  • Speaker.batas_durasi_hari(self) -> int (mengembalikan nilai 2)
Batasan dan Validasi Aturan Bisnis:
  • Class Perlengkapan tidak boleh dapat diinstansiasi secara langsung; Python harus memunculkan TypeError jika dicoba instansiasi.
  • Batas peminjaman wajib sesuai aturan: Proyektor maksimal 3 hari, Kamera maksimal 2 hari, Speaker maksimal 2 hari.
Hint Awal untuk Tim 2: Gunakan modul bawaan from abc import ABC, abstractmethod. Atribut self._tersedia = True diatur pada konstruktor class induk Perlengkapan. Method ubah_ketersediaan cukup melakukan self._tersedia = bool(status).
Unduh Starter Tim 2 (perlengkapan.py)

Tim 3: Pengajuan Transaksi (peminjaman.py)

Tanggung Jawab Fitur: Mengelola siklus transaksi peminjaman, memvalidasi durasi dan tanggal, serta mereservasi barang.

Item OOP yang Wajib Diterapkan:
  • Object Aggregation: Mengaitkan objek Mahasiswa dan objek Perlengkapan ke dalam objek transaksi Peminjaman.
  • State Machine Invariant: Menjaga siklus status baku (DIAJUKAN, DISETUJUI, DITOLAK, SELESAI) menggunakan kamus TRANSISI_SAH.
  • Encapsulation: Seluruh state transaksi dilindungi dan hanya dibaca via @property.
  • Validasi Domain: Memvalidasi urutan tanggal, batas maksimal durasi barang, dan ketersediaan barang.
  • Inter-module Effect: Otomatis mereservasi barang dengan memanggil barang.ubah_ketersediaan(False) saat pengajuan valid dibuat.
Metode yang Wajib Dibuat:
  • Peminjaman.__init__(self, id_peminjaman, mahasiswa, barang, tanggal_pinjam, tanggal_kembali)
  • Peminjaman.id_peminjaman(self) -> str (property)
  • Peminjaman.mahasiswa(self) -> Mahasiswa (property)
  • Peminjaman.barang(self) -> Perlengkapan (property)
  • Peminjaman.tanggal_pinjam(self) -> date (property)
  • Peminjaman.tanggal_kembali(self) -> date (property)
  • Peminjaman.status(self) -> str (property, status awal: 'DIAJUKAN')
  • Peminjaman.durasi_rencana_hari(self) -> int (menghitung selisih hari rencana)
  • Peminjaman.ubah_status(self, status_baru: str) -> None (validasi state machine)
Batasan dan Validasi Aturan Bisnis:
  • Peminjam wajib bertipe Mahasiswa (peran mahasiswa). Tolak role lain dengan PermissionError.
  • Barang wajib turunan dari Perlengkapan.
  • Tanggal kembali tidak boleh mendahului tanggal pinjam (bangkitkan ValueError).
  • Durasi peminjaman minimal 1 hari dan tidak boleh melebihi barang.batas_durasi_hari() (bangkitkan ValueError).
  • Barang wajib sedang berstatus tersedia (barang.tersedia == True). Jika sedang dipinjam, tolak dengan ValueError.
  • Perubahan status ke selain transisi sah pada TRANSISI_SAH wajib membangkitkan ValueError.
Hint Awal untuk Tim 3: Gunakan helper datetime.strptime(string_tgl, "%Y-%m-%d").date() agar method Anda dapat menerima input string maupun objek date kalender secara fleksibel. Selisih hari didapat dengan (tgl_kembali - tgl_pinjam).days.
Unduh Starter Tim 3 (peminjaman.py)

Tim 4: Layanan Persetujuan (persetujuan.py)

Tanggung Jawab Fitur: Memproses persetujuan atau penolakan pengajuan oleh Petugas yang berwenang.

Item OOP yang Wajib Diterapkan:
  • Service Class: Class LayananPersetujuan sebagai pengelola logika bisnis keputusan.
  • Static Method (@staticmethod): Method alasan_valid(alasan: str) -> bool dibuat tanpa memerlukan atribut instansi self.
  • Authorization Check: Memvalidasi kewenangan petugas (petugas.role == 'petugas').
  • Inter-object Coordination: Mengubah status transaksi via peminjaman.ubah_status() dan melepaskan ketersediaan barang jika ditolak.
Metode yang Wajib Dibuat:
  • LayananPersetujuan.alasan_valid(alasan: str) -> bool (static method)
  • LayananPersetujuan.putuskan(self, peminjaman, petugas, disetujui: bool, alasan: str = "") -> bool
Batasan dan Validasi Aturan Bisnis:
  • Hanya pengguna ber-role 'petugas' yang berhak memutuskan. Jika selain petugas, bangkitkan PermissionError.
  • Hanya peminjaman berstatus 'DIAJUKAN' yang dapat diputuskan. Jika berstatus lain, bangkitkan ValueError.
  • Jika ditolak (disetujui == False): teks alasan wajib valid (minimal 5 karakter tidak kosong via alasan_valid). Jika alasan tidak valid, bangkitkan ValueError.
  • Jika ditolak, status barang wajib otomatis dikembalikan menjadi tersedia: peminjaman.barang.ubah_ketersediaan(True).
Hint Awal untuk Tim 4: Dekorator @staticmethod ditaruh tepat di atas method alasan_valid. Pada method putuskan, jika disetujui ubah status ke 'DISETUJUI'; jika tidak disetujui ubah status ke 'DITOLAK' dan jangan lupa lepaskan barang dengan peminjaman.barang.ubah_ketersediaan(True).
Unduh Starter Tim 4 (persetujuan.py)

Tim 5: Pengembalian dan Denda (pengembalian.py)

Tanggung Jawab Fitur: Memproses penyelesaian transaksi saat barang dikembalikan serta menghitung denda keterlambatan kalender.

Item OOP yang Wajib Diterapkan:
  • Abstract Base Class (ABC): Class abstrak KebijakanDenda(ABC).
  • Abstract Method (@abstractmethod): Method hitung_denda(tanggal_kembali, tanggal_aktual) -> int.
  • Strategy Pattern / Polimorfisme: Class konkret DendaHarian(KebijakanDenda) dengan tarif Rp5.000 per hari kalender terlambat.
  • Dependency Injection: LayananPengembalian menerima objek kebijakan denda pada constructor __init__(self, kebijakan_denda=None).
  • Transaction Finalization: Menyelesaikan transaksi (status SELESAI) dan mengembalikan barang ke status tersedia.
Metode yang Wajib Dibuat:
  • KebijakanDenda.hitung_denda(self, tanggal_kembali, tanggal_aktual) -> int (abstract method)
  • DendaHarian.__init__(self, tarif_per_hari: int = 5000)
  • DendaHarian.hitung_denda(self, tanggal_kembali, tanggal_aktual) -> int
  • LayananPengembalian.__init__(self, kebijakan_denda: KebijakanDenda = None)
  • LayananPengembalian.proses(self, peminjaman, tanggal_aktual) -> dict
Batasan dan Validasi Aturan Bisnis:
  • Hanya transaksi berstatus 'DISETUJUI' yang dapat dikembalikan. Tolak status 'DIAJUKAN', 'DITOLAK', atau 'SELESAI' (mencegah pengembalian ganda) dengan ValueError.
  • Tanggal aktual pengembalian tidak boleh sebelum tanggal pinjam (bangkitkan ValueError).
  • Perhitungan keterlambatan kalender: hari_terlambat = max(0, (tanggal_aktual - tanggal_kembali).days).
  • Denda adalah hari_terlambat * tarif_per_hari. Jika tepat waktu, denda adalah Rp0.
  • Saat transaksi selesai, ubah status ke 'SELESAI' dan kembalikan barang: peminjaman.barang.ubah_ketersediaan(True).
Hint Awal untuk Tim 5: Gunakan max(0, selisih_hari) agar tidak menghasilkan denda minus jika barang dikembalikan lebih awal. Di dalam LayananPengembalian, gunakan nilai default: self._kebijakan_denda = kebijakan_denda or DendaHarian().
Unduh Starter Tim 5 (pengembalian.py)

Tim 6: Riwayat dan Laporan (laporan.py)

Tanggung Jawab Fitur: Menyajikan penyaringan riwayat transaksi, ringkasan eksekutif, dan pencatatan audit log otomatis via Custom Decorator.

Item OOP yang Wajib Diterapkan:
  • Custom Decorator: Fungsi dekorator @catat_operasi menggunakan functools.wraps.
  • Separation of Concerns: Pencatatan log pemanggilan method dipisahkan secara transparan dari logika pelaporan.
  • Collection Aggregation: Mengelola list transaksi bersama tanpa mengubah state asli objek peminjaman.
  • Filtering Method: Method riwayat yang mendukung penyaringan berdasarkan NIM dan/atau status secara modular.
Metode yang Wajib Dibuat:
  • catat_operasi(method) (fungsi dekorator)
  • LaporanPeminjaman.__init__(self, daftar_peminjaman: list)
  • LaporanPeminjaman.riwayat(self, nim: str = None, status: str = None) -> list (didekorasi @catat_operasi)
  • LaporanPeminjaman.ringkasan(self) -> dict (didekorasi @catat_operasi)
  • LaporanPeminjaman.log_operasi(self) -> list (membaca salinan catatan audit)
Batasan dan Validasi Aturan Bisnis:
  • Dekorator tidak boleh memodifikasi atau mengganti nilai kembalian (return value) asli dari method yang didekorasinya.
  • Kamus ringkasan eksekutif wajib memuat: total_transaksi, diajukan, disetujui, ditolak, selesai, dan total_denda.
Hint Awal untuk Tim 6: Di dalam fungsi pembungkus (wrapper decorator), panggil hasil = method(self, *args, **kwargs). Kemudian buat dictionary catatan yang merekam method.__name__ dan timestamp waktu, lalu simpan ke self._log_operasi.append(catatan), lalu return hasil.
Unduh Starter Tim 6 (laporan.py)

Tim 7: Integrasi Aplikasi (main.py)

Tanggung Jawab Fitur: Mengorkestrasi seluruh modul dari Tim 1 s.d. 6 menjadi alur aplikasi yang siap dipresentasikan.

Item OOP yang Wajib Diterapkan:
  • System Orchestration: Menghubungkan seluruh class dan layanan dari 6 tim lainnya.
  • Fixture Synthesis: Fungsi buat_data_demo() menyiapkan data awal tanpa menyalin NIM mahasiswa riil.
  • Exception Handling: Menangkap error penolakan dengan blok try ... except ValueError agar program tidak crash saat menguji kasus gagal.
  • Reproducible Execution: Seluruh alur dapat dijalankan berulang kali dengan hasil yang konsisten.
Metode dan Fungsi yang Wajib Dibuat:
  • buat_data_demo() -> dict (menyiapkan minimal 3 Mahasiswa, 2 Petugas, dan 3 Perlengkapan: Proyektor, Kamera, Speaker)
  • jalankan_demo() -> None (menjalankan alur demonstrasi lengkap)
Skenario Wajib yang Harus Ditampilkan pada Demo:
  • Skenario 1 (Alur Sukses Utama): Mahasiswa mengajukan Proyektor 3 hari, Petugas menyetujui, dikembalikan 2 hari terlambat, sistem mencatat denda Rp10.000, status barang kembali tersedia.
  • Skenario 2 (Kasus Gagal: Durasi Melebihi Batas): Pengajuan Kamera selama 4 hari ditolak oleh validasi durasi (batas Kamera adalah 2 hari).
  • Skenario 3 (Kasus Gagal: Barang Sedang Dipinjam): Pengajuan ditolak karena barang sedang berstatus tidak tersedia (dipinjam orang lain).
  • Skenario 4 (Kasus Gagal: Penolakan oleh Petugas): Petugas menolak pengajuan dengan alasan valid, status menjadi DITOLAK, dan barang kembali tersedia.
  • Skenario 5 (Pelaporan): Menampilkan riwayat terfilter, ringkasan eksekutif, dan catatan log audit dekorator.
Hint Awal untuk Tim 7: Gunakan tanggal statis sintetis (contoh: 2026-10-15) agar hasil demo selalu konsisten. Jangan menulis ulang aturan bisnis di main.py; selalu delegasikan keputusan dan perhitungan ke method milik tim yang berwenang.
Unduh Starter Tim 7 (main.py)

Tidak diizinkan melakukan perpindahan status langsung dari DIAJUKAN ke SELESAI atau memproses pengembalian pada transaksi yang berstatus DITOLAK.

7. Ekspektasi Hasil dan Indikator Capaian Goals

Bagian ini memberikan gambaran konkret mengenai hasil akhir yang diharapkan ketika seluruh komponen dari Tim 1 s.d. 7 berhasil diintegrasikan dengan benar. Mahasiswa dapat menggunakan tolak ukur ini untuk memverifikasi apakah sistem mereka telah memenuhi seluruh kriteria kelulusan studi kasus.

Indikator Keberhasilan Goals

  • Hak Akses Terjaga: Hanya Mahasiswa yang bisa mengajukan dan hanya Petugas yang bisa menyetujui / menolak transaksi.
  • Polimorfisme Berjalan: Batas pinjam diatur mandiri oleh class barang: Proyektor 3 hari, Kamera 2 hari, Speaker 2 hari.
  • Reservasi Otomatis: Saat pengajuan dibuat, barang otomatis berubah status menjadi tidak tersedia (tersedia = False).
  • Alasan Penolakan Valid: Petugas wajib menyertakan alasan minimal 5 karakter saat menolak pengajuan, dan barang otomatis dilepaskan kembali menjadi tersedia.
  • Kalkulasi Denda Akurat: Pengembalian terlambat 2 hari pada Proyektor tepat menghitung denda Rp10.000 (tarif Rp5.000 per hari keterlambatan kalender).
  • Audit Trail Aktif: Custom decorator @catat_operasi mencatat metadata pemanggilan laporan tanpa merusak return value method.
  • Penanganan Error Anggun: Seluruh kasus penolakan ditangani dengan blok try...except sehingga program tidak berhenti mendadak (crash).

Cara Menjalankan Sistem

Setelah berkas kode dari seluruh tim digabungkan ke dalam direktori kerja, jalankan skrip utama main.py melalui salah satu cara berikut:

  • Melalui Terminal / Konsol:
    Buka terminal di folder kerja dan ketikkan perintah:
    python main.py
  • Melalui VS Code / Editor:
    Buka berkas main.py, lalu klik tombol Run Python File (ikon segitiga di pojok kanan atas) atau tekan tombol Ctrl + F5.
  • Uji Assertion Otomatis:
    Jika tim menambahkan flag uji unit, jalankan dengan:
    python main.py --test
